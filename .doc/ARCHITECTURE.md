# Cuter Weblinks – Technical Architecture

Primary technical reference for developers and AI agents working on this codebase.

**Version**: 1.5.1
**Last Updated**: August 2026

---

## What this is

A Joomla **site module** (`mod_cuterweblinks`) that reads entries from the **Weblinks** component and renders them as a styled list. It does not have its own database tables, no AJAX, no JavaScript, no admin pages beyond the standard Joomla module-parameters form. All logic lives in one helper class and one template.

**Hard dependency**: The Weblinks component (`com_weblinks`) is **not** part of Joomla core (hasn't been for a while — see `README.md`). It must be installed separately (e.g. from https://github.com/joomla-extensions/weblinks) for the `#__weblinks` / `#__categories` tables and the `weblink.go` route to exist. This module does not check for its presence; if the tables are missing, the query simply fails.

## File Structure

```
cuterweblinks/
├── mod_cuterweblinks.php              # Entry point: loads params, calls helper, registers CSS, requires layout
├── mod_cuterweblinks.xml              # Manifest: module config form (all params), update server, files/media mapping
├── src/Helper/CuterWeblinksHelper.php # All logic: DB query (getLinks) + layout CSS resolution (getStyleFilename)
├── tmpl/default.php                   # Default layout — renders the <ul class="cuterweblinks"> list
├── media/css/default_style.css        # Styling for the default layout (list, grid-with-image variant, hover)
├── language/{en-GB,de-DE}/            # mod_cuterweblinks.ini (field labels) + .sys.ini (module name in Joomla's module chooser)
├── build.xml                          # Phing target `package`: zips the extension, writes .releases/update.xml with checksums
└── .releases/                         # Generated build output (zip + update.xml) — never hand-edit, regenerated by `phing package`
```

There is no `services/`, no `Dispatcher.php`, no admin controller — this is about as small as a Joomla module gets.

## Request Flow

```
mod_cuterweblinks.php
  → CuterWeblinksHelper::getLinks($params, $app)   // DB query, returns array of link objects (or empty)
  → if empty: return (nothing rendered, no module chrome)
  → CuterWeblinksHelper::getStyleFilename(...)      // resolves which CSS to load for the active layout
  → ModuleHelper::getLayoutPath(...) → require tmpl/default.php  // renders the <ul>
```

`tmpl/default.php` is a dumb view: it reads properties off each `$link` object and outputs prologue/list/epilogue. All decisions (what fields to select, how to filter, how to resolve the image URL) happen in the helper.

## `CuterWeblinksHelper::getLinks()` — the only query in the codebase

**File**: `src/Helper/CuterWeblinksHelper.php`

Builds one query against `#__weblinks` LEFT JOIN `#__categories`. Key behavior, in order:

1. **Field selection is conditional** — `weblinks.images`, `weblinks.hits`, `weblinks.description` are only selected if the corresponding display param is enabled. `categories.title AS category` only if the `category` param is on. This keeps the query minimal but means `tmpl/default.php` must always null-coalesce these (`$link->description ?? ''` etc.) since the property may not exist on the row at all.
2. **Filters applied** (all mandatory, in this order):
   - `weblinks.state = 1` and `categories.published = 1`
   - **View-access filtering** (since 1.5.1): `weblinks.access` and `categories.access` are both checked against `$app->getIdentity()->getAuthorisedViewLevels()`. Before 1.5.1 this was missing entirely — any anonymous visitor could see titles/descriptions of Registered- or Special-access links. If you touch this query, keep both checks; category access does **not** imply weblink access or vice versa.
   - Category filter (`catid IN (...)`) — skipped entirely if `categories` param is `['all']`.
   - Language filter (`weblinks.language IN (current tag, '*')`) — only if the `languages` param is enabled.
3. **Ordering**: `ORDER BY weblinks.{ordering} {direction}`, defaults `title` / `ASC` (since 1.5.1 — see below). `$ordering` is inserted into `quoteName()` directly from module params; the field is a fixed `<list>` in the manifest (`title|ordering|hits|created`), not free text, but if you ever add a way to set it outside that form, validate against the allowed set first.
4. **Postprocessing** (after `loadObjectList()`):
   - `title` is stripped of tags.
   - `reference` is built via `Route::_('index.php?option=com_weblinks&task=weblink.go&id=' . $id)` — this is how the frontend link actually resolves through the (separately installed) Weblinks component.
   - `imageUrl` is resolved from the JSON `images` field (`image_first` falling back to `image_second`), with Joomla's `#...` image-attributes suffix stripped.

### The 1.5.1 default-value bug (fixed, keep it fixed)

`$params->get('ordering')` and `$params->get('direction')` used to be called **without a default**. Through the normal "New Module" admin form this never showed up (the `<select>` always submits *some* value, even untouched). It broke for module rows created any other way — direct DB inserts, migrations, or old rows saved before these fields existed in the manifest — producing `SQL error 1054: Unknown column 'weblinks.' in order clause` and taking down the whole page render (not just the module). Fixed by defaulting to `'title'` / `'ASC'`, matching the XML manifest defaults. **Lesson for future params**: any param read via `$params->get()` inside the query builder should carry an explicit default matching its manifest default — don't rely on the admin form always populating it.

## Module Configuration (`mod_cuterweblinks.xml`)

All params live in one `basic` fieldset plus a standard `advanced` fieldset (layout/moduleclass_sfx/cache — Joomla boilerplate, not module-specific logic).

| Param | Type | Default | Consumed in |
|---|---|---|---|
| `categories` | category (multi, com_weblinks) | `all` | `getLinks()` — catid filter |
| `count` | number | `5` | `getLinks()` — `setLimit()` |
| `ordering` | list (title/ordering/hits/created) | `title` | `getLinks()` — `ORDER BY` column |
| `direction` | list (ASC/DESC) | `asc` | `getLinks()` — `ORDER BY` direction |
| `image` | radio | `0` | `getLinks()` field selection + `tmpl/default.php` |
| `description` | radio | `0` | same |
| `category` | radio | `0` | same |
| `hits` | radio | `0` | same |
| `target` | radio (0/1) | `0` | `tmpl/default.php` — `_top` vs `_blank` |
| `languages` | radio | `0` | `getLinks()` — language filter |
| `prologue` / `epilogue` | editor (safehtml) | — | `tmpl/default.php` |

Field labels/descriptions live in `language/*/mod_cuterweblinks.ini` — every `MOD_CUTERWEBLINKS_FIELD_*` key referenced by the XML must have an entry in **both** `en-GB` and `de-DE`, or the admin form falls back to showing the raw language key.

## Compatibility

- **PHP**: `php_minimum` 8 in the manifest (permissive floor; tested against 8.3).
- **Joomla**: `build.xml`'s `targetplatform` regex is the single source of truth for which Joomla versions the update server advertises this extension as compatible with. It does **not** gate installation (Joomla installs the package regardless) — it only controls whether the built-in Joomla Updater offers the update. Keep it in sync manually when a new Joomla minor drops; nothing enforces this automatically. Verified functionally against Joomla 6.2.0-beta1 (August 2026) using a disposable Docker stack (PHP 8.3-apache + MySQL 8) — see `CHANGES.md` 1.5.1 entry for what was checked.
- **`.releases/`**: build output, not source. Regenerated by `phing package` (reads version from `mod_cuterweblinks.xml`, rebuilds the zip, recomputes checksums, rewrites `update.xml`). If you have an IDE with Phing integration configured against this project, it may rebuild these files automatically on save of `build.xml` or similar — check `git status` before committing and don't fold unexpected `.releases/` diffs into unrelated commits unless you intended to cut a release.

## Development Patterns

**Adding a new display param** (e.g. a new toggle like `hits`):
1. Add the `<field>` to `mod_cuterweblinks.xml` (`basic` fieldset), with a sensible `default`.
2. Add its label/description keys to **both** language `.ini` files.
3. In `CuterWeblinksHelper::getLinks()`: read it with `$params->get('name', <same default as XML>)`; if it affects field selection, add to the conditional `$fields[]` block.
4. In `tmpl/default.php`: read the corresponding `$link->property ?? ''` (never assume the property exists — see field-selection note above) and render conditionally.

**Adding a new layout**: Joomla's standard `modulelayout` mechanism — drop a new file next to `tmpl/default.php` (e.g. `tmpl/grid.php`), it becomes selectable in the module's Advanced tab automatically. `CuterWeblinksHelper::getStyleFilename()` will look for a matching `media/css/{layout}_style.css` and fall back to `default_style.css` if none exists.

**Testing without a real server**: this module has no unit tests. Functional verification in this project has been done by standing up a disposable Joomla instance in Docker (official Joomla source zip + PHP-apache + MySQL containers), installing `com_weblinks` separately, then installing this module's zip via `cli/joomla.php extension:install`. See `CHANGES.md` for what was verified this way for 1.5.1.
